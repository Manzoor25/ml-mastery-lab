# 18 Real-world case studies

Capstones. A vague business ask, a framed problem, data, features, a model, an evaluation, a deployment sketch, a monitoring plan, and a note a stakeholder can read.

Nothing in this section has been run. Folders are created when the work starts.
Status lives in [PROGRESS.md](../PROGRESS.md). Run a project with `python main.py`
once its folder exists. Raw data is downloaded by the script and is not committed.

| Project | What it covers |
| --- | --- |
| `01-customer-churn` | Framing, features, model, threshold, deployment sketch, monitoring, stakeholder note |
| `02-credit-default` | A risk model with an explanation a reviewer can ask for |
| `03-fraud-cost-sensitive` | A fraud model whose threshold comes from a cost matrix |
| `04-demand-forecasting` | A forecast tied to an inventory decision and a stockout cost |
| `05-search-ranking` | Ranking features, a click model, and a ranking metric that is not click rate alone |
| `06-support-ticket-routing` | Text classification into queues, with the cost of a wrong queue |
| `07-document-qa` | A RAG case study that separates retrieval from answer quality |
| `08-uplift-marketing` | Uplift or a dynamic-pricing style decision, against targeting likely buyers |
